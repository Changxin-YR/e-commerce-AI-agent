# V1.2 Codex 真实施工手册、阶段门槛与交接格式

状态：交给开发代理的施工协议，不是开发完成说明。默认 Windows PowerShell，工作区是两个独立项目。目录内其他适用 AGENTS.md/README 应先阅读，保留已有代码与数据。

## 1. 决策无需反复问的部分

题目、单机本地运行、技术栈、数据源、ICP、工具权限、五/六页面最终范围、B0/B1/B2 研究定义、无外发、无生产店铺写操作已经确定。可自主处理构建/测试缺陷和可逆性重构。不要为普通依赖安装、建立数据库、修复测试逐步请求确认。

需要用户配合的输入清单：**模型提供方合法凭据与额度（仅模型阶段）**；**真实人工标注及复核（研究阶段）**；**学校任务书/格式（论文格式阶段）**。若输入尚缺，就完成其他工作，独立标 BLOCKED；不能替代用户作出人工标签、购买服务或添加收费调用。

## 2. 首次执行入口

Windows PowerShell 示例（解压本包后；`python` 应以 doctor 实测版本为准）：

```powershell
# Windows PowerShell，先在当前项目目录运行
cd .\ecommerce-agent-thesis
python scripts\handoff_check.py
# 在本目录中开启 Codex，会话中粘贴根目录 CODEX_START.md 内容
```

`handoff_check.py` 仅检查交接包文档/模板及引用存在，**不检查应用功能**。Codex 真正开工后应实现 `scripts/manage.py` 的 doctor、测试、导入、服务、对账、实验等命令，且确实运行；没有脚本时不能写 README 假装它已经存在。

项目交接包自带 `AGENTS.md` 指向对应详细文件；Codex 也可以按该启动指令自动继续。只在用户指定的目录内工作，不全盘检索代码或直接改另一个论文项目。

## 3. 建议以实际 PR/小批次逐步推进

| 顺序 | 电商验收 | 获客验收 | 门槛 |
|---|---|---|---|
| 0 | doctor、依赖锁与目录；状态文件 | 同左 | 实际环境可读、现有代码保留 |
| 1 | UCI 官方文件复下载、哈希、实际审计 | 真实候选获取/有来源的导入和 12 家试采 | 实际源文件和失败状态可核验 |
| 2 | 数据库迁移、行分类、定点金额、独立对账 | 企业/快照/证据数据模型、身份/D1判断 | 冻结的小范围数据可独立核验 |
| 3 | Web 导入与 9/10 月 API/结果 | Web 列表/企业详情/证据定位/盲标注 | 浏览器端完成真实流程 |
| 4 | 支持多轮的 B1、校验 B2、持久澄清、8 工具 | B1 直接判断、B2 证据流程、人工复核路由、草稿 | 真实模型冒烟有记录；无 Key 则仅阻断模型段 |
| 5 | 完整五页面、边界、安全、E2E | 完整六页面、采集和证据安全、E2E | 核心用例自动+浏览器实测 |
| 6 | 30开发题/100测试题、gold、冻结 | 12试采、人审规范、40/120候选、gold、冻结 | 人工材料真实、版本冻结、无泄漏 |
| 7 | B0/B1/B2 批量与分析 | B0/B1/B2 批量与分析 | 额度与完整 run 记录，指标可重算 |
| 8 | 独立论文正文、引用、答辩材料 | 同左 | 论文每个数值有证据，缺格式如实标注 |

顺序 0→1→2→3 是第一轮重点；两篇的“业务第一片”都**不依赖模型密钥**。不为追求一次完成而提前构建完整平台；对可以并行的独立小任务可安排适度并行，但不能共享可变数据库或代码。

## 4. E-S1 与 L-S1 的最小现场验收

**电商：**提交原始官方数据文件，`source sha256` 一致，54万行与互斥分类对账；重复导入不重复计数；两月精确金额与 `13` 一致；浏览器刷新后历史结果仍可查询；实际完成一次图表或表格展示及运行日志。

**获客：**真实候选来源与企业身份可追溯；成功/失败网页快照均留痕；点击证据可定位原文字段；未核实的企业不会自动匹配；盲标注只在真人提交后标注；公网非预期地址和网页命令注入的测试都安全拒绝；12 家试验的实际结果能核验。若没有满足分类可行性的人工复核，不允许启动正式 160 家研究样本采集。

**首轮完成报告必须包含：**运行环境，Git SHA，真实数据/来源 SHA，完成的具体 API 与页面，已执行测试命令+退出码+测试数，实际页面截图或视频证据路径，未通过项/阻碍，下一阶段具体任务。禁止用方案文档或伪造截图代替。

## 5. 每个 Codex 会话结束前的交接

保持下列文件最新（首版项目脚手架提供未开始模板，正式由执行事实更新）：

- `docs/STATUS.json`：唯一机器状态来源，工程/数据/模型/人工/实验/论文分别标 `NOT_STARTED|IN_PROGRESS|PASS|FAIL|BLOCKED` 和证据路径。
- `docs/STATUS.md`：和 JSON 同步的中文摘要。
- `docs/DECISIONS.md`：实际取舍、冲突、版本、理由和影响。
- `docs/EVIDENCE_INDEX.md`：实际执行命令、时间、退出码、源文件 hash、run_id、日志/截图路径。
- `docs/KNOWN_ISSUES.md`：未解决问题及严重程度。
- `docs/NEXT_SESSION.md`：下一次会话的唯一入口，指向项目实际状态和具体未完任务。

建议每个批次保持 Git commit 可追溯。若是已有仓库，Codex 必须先展示 `git status`，不可丢弃用户未提交更改、强推或重写历史。没有本地 Git 配置时先保存 patch 和改动文件清单。
