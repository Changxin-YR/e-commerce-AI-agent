## 3. 价格规范化的独立验证

原OOXML存在如2.5499999999999998一类表示尾差。第二个脚本直接读取XML数值，以Decimal检查价格到0.001 GBP网格的距离，随后使用整数千分英镑聚合。

| 项目 | 实测结果 |
|---|---:|
| 检查的价格数 | 541,909 |
| 与三位网格有非零微小差值 | 51,170 |
| 最大绝对差 | 7E-13 GBP |
| 差值超过1E-9 GBP | 0 |
| 规范化后仍为0.001 GBP | 4 |

据此为当前快照设定：保留原始价格表示；差值≤1E-9时规范化到0.001，使用ROUND_HALF_UP；规范化价格存整数千分英镑；内部以整数精确聚合；展示层汇总后再按ROUND_HALF_UP显示两位。任一数值超阈值则阻断此固定精度规则，不能静默舍入。

这是本研究明确选择、经过逐行检查的规范化规则，不是任意CSV的通用处理方法。原文件和转换痕迹必须保留。SQLite NUMERIC声明本身不能保证Decimal语义，生产实现需按该契约选择整数或显式Decimal计算。

## 4. 首个切片可用的月度参考

下列计算来自第二个独立脚本，不调用未来系统的聚合函数。采用以下冻结研究口径：

- 正向：非C/c发票，数量>0且规范化单价>0。
- 取消：C/c发票，数量<0且规范化单价>0；取金额绝对值。
- 净额：正向减取消。
- 原始重复行与缺客户号的行保留；POST、BANK CHARGES、M等符合条件的条目纳入。
- 使用原始行时间所在月份，期间采用左闭右开日历区间。
