# V1.2 评估与冻结协议：保证论文可复核

日期：2026-11-01。与 `04_EXPERIMENT_PROTOCOL.md` 共同使用；此文件固定尚未明确的运行字段、数学分母、准入门禁和批次步骤。**当前没有正式实验结果。**

## 1. 三条研究证据链

- 电商：`真实文件哈希 → 解析/分类版本 → 计算版本 → 独立参考值 → 测试任务 → 方案预测 → 评分器 → 论文数值`。
- 获客：`真实企业来源 → 身份核对 → 公开快照哈希 → 人工可见证据 → 人类 gold → 固定方案运行 → 预测/动作 → 评分器 → 论文结论`。
- 运行：`代码 commit → 依赖锁/环境 → 配置和提示词哈希 → 每次模型尝试 → 输出/错误 → 生成表图`。

每一个统计表必须能反向定位到不可覆盖的逐任务记录。真实数据/软件测试 fixture/人工标注/模型建议用不同目录与 `source_kind`，不能混算。

## 2. 正式测试的前置门禁

以下条件同时满足，才能对某篇运行正式 B1/B2：

1. 实际数据已固定，下载/采集及数据处理有哈希、来源和许可记录。
2. 样本/任务 ID 和开发/测试划分、分组规则已冻结，没有跨组重复或信息泄漏。
3. 电商独立标准答案在开发侧复核通过且正式 gold 人工审查状态明确；获客必须有真实人工确认的测试 gold。未得到任何人工标签时**不得**生成监督准确率。
4. B0/B1/B2 的可访问输入、公共工具、权限、基础重试和最大请求/token 预算与输出 schema 已记录。增强组额外业务步骤可用，但额外调用消耗同一硬上限。
5. 模型精确 ID、provider、温度、接口版本、SDK/依赖锁文件、提示词哈希与源码 commit 固定。真实调用冒烟成功，提供方用量字段能解析或标 unknown。
6. 用户已经提供可用模型配置与有界额度；`MODEL_MAX_TOTAL_REQUESTS` / token 等开关实际有效。尚未满足只运行无模型工程测试。
7. 评分器必须先以 test_fixture 做自测：纯对、纯错、无回答、预算中断、证据无效均能返回预期分数。**评分器只在全部预测写盘之后**读取正式 gold。
8. 生成 `eval/freeze_manifest.json`（含内容哈希）并禁止覆盖。复查改动进入新的 experiment_id，不覆盖原始结果。

## 3. 建议数据结构与唯一键

`eval/dev.jsonl` 与 `eval/test.jsonl` 中每行拥有不可空的 `case_id`、`split`、`scenario_type`、`dataset_or_snapshot_ref`、`input`、`expected_action_category`、`rubric_id`；测试集不存给运行模型读取的答案。电商可回答题 gold 另存 `eval/gold/reference_answers.jsonl`，每条含 `metric`, `period`, `filters`, `expected_exact_string`, `tolerance`, `reference_script_hash`, `human_review_state`。澄清题保存必需字段与固定答复脚本；不支持字段题保存 `UNSUPPORTED_METRIC`。实数金额真值采用 Decimal 字符串而非 JSON float。

获客 `company_id + snapshot_bundle_hash + icp_version` 为标注对象的逻辑唯一键，`gold_label ∈ {match,non_match,insufficient_evidence}`，另保留 H1/H2/D1/A1、标签人员和证据。未完成人审的记录 `human_verified=false`，不纳入完成的人工 gold；不得把模型判断写回 gold 文件。

每次运行唯一键 `(experiment_id, case_id_or_company_id, variant, repeat_index)`；写入原始记录后只追加不更新。失败也保留 `predicted_class=null, run_status=FAIL, error_code, attempts`。未实际尝试的标 `NOT_RUN` 而非自动计失败。重跑必须形成新的 experiment_id 或明确新 attempt，不得复用已写结果文件。

## 4. 基线公平与禁止数据泄漏

- 两篇 B0 都是非模型、可复核的规则/模板方案，不作为“需要故意输给 Agent”的弱桩。B0 的范围有限时单独给覆盖率，并在共同任务子集做公平比较。
- 电商 B1 是真实可多轮工具循环的基础 Agent：能够读取工具输出和错误、继续调用、澄清或结束；B2 在此基础上增加显式口径检查、跨工具对账与有界修复。通用 schema、基础输入校验和授权边界对双方相同；不能把所有校验都关闭来故意让 B1 失败。
- 获客 B1 与 B2 **必须获得完全相同的冻结网页正文、主体身份信息、ICP 定义和字段取值要求**。B2 可增加证据定位与逻辑校验；运行阶段不能联网、不能读人工标签。人工修订后数据仅用于 assisted 结果，绝不用于自动对照主表。
- 开发集允许改提示词和业务规则；一旦正式 test 被查看即进入已使用状态。针对 test 发现的程序 bug 修复可以记录新版本并重新运行，但不得称新跑的仍是“首次未见测试”或删掉旧不利结果。其他调参须另备保留集。

## 5. 电商指标与分母

正式主集 90 条（基础指标25，多条件20，多步骤20，需追问15，不支持10），故障集10条独立报告；开发集30条。检查任务分类在冻结前可合理修订；正式冻结后不改。

- **精确计算正确率**：`准确完成全部关键数值的可回答题数 / 可回答题总数`；无效输出和超时计不正确。金额匹配依据原始三位精度，人民币/英镑和商品金额口径不可混用。
- **全任务成功率**：`满足每题预定义所有必要状态/字段/计算条件的题数 / 所有已安排且实际尝试的任务数`；另报全部计划数与未运行数，正式完成要求未运行=0。
- **澄清正确率**：`准确问出冻结所需字段且没有乱用默认值的澄清题数 / 澄清题数`。固定答复脚本单独评价澄清后的完成；不在一个分母混入无需澄清题。
- **数据不支持处理率**：`正确拒绝无依据指标计算的题数 / 不支持类题数`；`unsupported` 不算失败的模型调用，但不得装作计算成功。
- **故障稳健性**：10 条故障注入主张“安全停止/有界恢复/状态正确”，**绝不**说是真实交易故障；与 90 条主集分表。
- **成本与性能**：每题耗时（含/不含人工等待分别统计）、模型调用、工具调用、重试和 token；未知价格不填 0 元。

数值容差、相同比例时的排名排序、基期 0 和日期缺失答案必须在 `eval/rubric.md` 写死。超过两位展示舍入不能影响内部真值。无模型 Key 时电商 B0、数据工具可以运行，但 B1/B2 不算正式已完成。

## 6. 获客指标与分母

设全部已冻结测试公司数为 N；真实人类标签属于 `match/non_match/insufficient_evidence`，类别样本数分别为 N_m、N_n、N_u，合计 N。取得**无效预测**（模型超时、格式无效）视为端到端错误，不能在总体分母中删掉。

- 主表为三行 gold × `match/non_match/insufficient_evidence/invalid_output` 四列预测的混淆矩阵。`invalid_output` **只是错误列，不是第四业务类**；对于每个真实业务类计算 `F1=2TP/(2TP+FP+FN)`，三类简单平均得 macro-F1。若某类真实 support=0，列明该类不可评价；并报告固定三类口径与支持类口径（不可只选择更好的一种）。
- `automatic_coverage = (action=accept 或 reject 且有效输出数量)/N`；`review_rate = (action=review_required 的数量)/N`。另外分别列有效模型输出率、运行失败率；若失效动作归 review_required，则明确说明 coverage+review=1 的计算规则，而非隐藏故障。
- `overassertion_rate = gold=insufficient_evidence 且 action∈{accept,reject} 的数量 / N_u`；N_u=0 标 NA，不写 0。
- `known_class_end_to_end_correct = 在 N_m+N_n 中动作自动且分类正确的数量 / (N_m+N_n)`；分母=0 标 NA。辅助报告有效预测子集的精确率，但不能取代端到端主指标。
- `evidence_span_validity = 起止位置/快照/原文字节对账通过的引用数 / 全部被审查引用数`，它是机器可以核对的**位置**指标；`evidence_semantic_support` 必须根据真实人工抽查记录，不能让自身模型决定自己所有证据都正确。
- 默认没有受训练或校验的类内相关性排序；固定 K 推荐结果只能是可选展示，并披露 company_id 造成的并列顺序，不能宣称衡量细粒度获客优先级或购买意向。

人工改后的 assisted 结果、人工耗时与复核覆盖率另表；禁止用人工修正后准确率与 B1 的原始自动准确率做直接结论。

## 7. 统计和完成判定

建议：确定性 B0 一次，B1/B2 各对全部测试对象独立运行三次（如真实额度不足，可以先记录缩小后的真实实验，但不得宣称原规模已完成）。重复运行不能视为增加独立样本。以同一题/公司配对比较，报告逐轮结果、均值/标准差和失败类型；若用 bootstrap，按题/公司为重采样单位，不按每次请求独立重采样。

`attempted + not_run = planned`；`valid_output + failed = attempted`。对每方案与每次重复均验证对账，任何不等式无法解释时阻断论文成绩表。实验汇总只从未篡改的 JSONL 生成，不能手写漂亮数字到 CSV 后声称为系统运行结果。

运行结束需形成：`freeze_manifest.json`、`raw/*.jsonl`、`results/metrics.csv`、`figures` 及生成脚本、`eval/error_analysis.md`、`thesis/claim_evidence_map.csv`；每一条论文中的效果主张能追溯到对应结果和运行 ID。

## 8. 目前缺什么才不能宣称“研究完成”

- 电商：用户环境中运行的项目、真实系统对账、模型权限和实际执行、人工抽查、正式冻结/实验、学院模板。
- 获客：12 家试采、正式候选池和实际快照、真实人工标签、模型权限和实际执行、冻结/实验、学院模板。

这些都不能通过完善文本计划代替；但它们**不阻止 Codex 今天开始工程开发**。
