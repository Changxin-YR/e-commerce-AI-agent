# V1.5 逐阶段施工路线：先实现全部业务功能，暂缓论文与正式实验

本文件是项目当前唯一开发阶段顺序。原则：**每阶段先编码和实测、提交证据、再进入下一阶段。** Codex 可在用户授权的本地工作区内自主修复普通构建和测试问题，但不得越过真实数据、外部模型收费授权、权限与安全边界。具体提示词在 `docs/dev/steps/`。

| 阶段 | 开发内容与必须落地的功能 | 阶段通过证据 | 阻碍时怎么继续 |
|---|---|---|---|
| D0 工程基础 | 检查 Git/环境，建 FastAPI /healthz、SQLAlchemy+Alembic 基座、Vue+TS+Vite 最小页面、doctor和测试命令、锁文件 | 后端/前端能本地启动、health通过、构建/测试命令可执行，保存退出码 | Python/Node 不可用则记录具体问题，完成可独立的结构和文档 |
| D1 真实数据 | 官方 UCI ZIP/XLSX 下载/验证、文件哈希、独立审计复跑、来源清单、字段字典和价格精度核验 | 与已审计文件哈希及质量计数相符；哈希不符则新版本审计 | 来源失败标 BLOCKED_DATA，绝不合成假经营数据 |
| D2 导入与数据库 | 完成最小数据表、迁移、受限上传/CLI、逐批导入、互斥分类、质量报告、跨ZIP/XLSX幂等与失败恢复 | 真实 541909 行导入、分类对账、重复导入不翻倍、异常输入被拒；迁移与测试通过 | 只有真实导入部分阻断，其他可独立测试继续 |
| D3 确定性统计 API | `/api/v1/datasets` /quality、`/metrics/monthly`、`/healthz`，先实现 3 核心工具；保存查询历史 | 对上 2011-09/10 独立对账值、E01-E09回归，OpenAPI响应真实 | 数据未到时可用 fixture 测API结构，**不得**标真实对账PASS |
| D4 前端首条业务链 | Vue 数据集导入/查看质量/选月份/查看精确值与覆盖警告、刷新取历史 | 真实浏览器导入→月度结果，截图/日志及 E10 证据 | 页面可以先展示空态，但不算真实功能完成 |
| D5 八工具齐备 | 增补质量、排名、期间比较、变化拆解、明细检查，统一 JSON Schema、查询上限、证据引用与异常码 | 八个工具均对真实数据工作；非法参数/无数据/不支持指标测试通过 | 与模型无关，优先单独做确定性代码 |
| D6 真正的 LangGraph | Provider 适配与合法预算、B1普通多轮工具调用、B2受限核验流程、同run追问/重启恢复、错误和持久记录 | 实际模型5场景冒烟、B1/B2真实tool_calls、恢复/预算/重复提交测试 | 无经授权模型配置时可完成功能代码与fake-provider测试，真实验证标 BLOCKED |
| D7 报告与五视图 | 经营概览、智能分析、报告详情、任务/实验记录与数据导入的五项完整功能；报告准确引用、导出与无模型历史读取 | 用户能从真实文件到生成有依据报告并回看、导出，状态/错误真实可见 | 无模型时先完成确定性报表、空态、历史页面 |
| D8 稳定性与安全 | 导入大小、ZIP/XLSX安全、参数化SQL、权限/Origin、XSS、公式导出、键保密、checkpoint恢复、浏览器核心 E2E | pytest/Vitest/Playwright及安全项目实际执行，日志和失败可追溯 | 有环境阻碍如实记录，不用手工替代声称自动通过 |
| D9 用户功能验收 | 完整功能矩阵与E01—E10复跑、安装/迁移/启动/停止、性能/资源观察、演示和修复 | `docs/dev/FEATURE_ACCEPTANCE.md` 逐项证据；标 `READY_FOR_USER_ACCEPTANCE` 供用户检查 | 依赖阻断项明确标 BLOCKED，不能声明全功能通过 |

### 对旧阶段的映射

D0≈E0；D1≈E1；D2-D4≈E-S1；D5-D6≈E-S2/E3；D7-D9≈E3 完整工程交付。旧 E4/E5 正式研究准备/学术对照和 E6 论文写作统一进入 `DEFERRED_UNTIL_USER_APPROVAL`，但已实现的日志、模型用量与开发测试结果必须保留。

### 每阶段结束时的固定报告

- Git status/commit（或没有 Git 的准确说明），改动文件及功能；真实执行命令、退出码和日志/截图证据。
- 阶段用例的 PASS/FAIL/BLOCKED/NOT_RUN 和阻碍原因；不得将写了代码等同运行通过。
- 更新 `docs/STATUS.json` 和同步 `docs/STATUS.md`，再更新 `docs/EVIDENCE_INDEX.md`、`docs/DECISIONS.md`、`docs/KNOWN_ISSUES.md` 和 `docs/NEXT_SESSION.md`。
- 只把本阶段确已通过的功能标 PASS。上一阶段未解决的阻断缺陷不得被下一阶段的“成功页面”掩盖。

### 权限与模型执行门槛

普通本地文件创建、安装开源依赖、运行可逆测试和修复错误可以自主推进。收费模型调用需用户明确授权且配置总请求/Token限额，不能因 `.env` 中已有 key 就推定授权。模型 Key 不进输出和 Git；不自动购买或充值，不擅自访问真实店铺/公网部署。真实数据下载按官方既定来源，下载或校验失败需保留原因并遵守用户网络权限。

### 到 D9 之前无需做的事情

不要写论文第1—6章、文献综述、论文图表、答辩PPT；不要启动正式90+10题批量 B1/B2 实验或追着统计显著性写结论。开发中形成的真实测试、日志、组件设计和数据来源属于工程产物，必须保留。论文阶段由用户明确单独开始。
