# V1.5：开发时统一处理的残余歧义

此页只修正易导致实现不一致的契约，不改变 V1.4 的研究数据或业务定义。

1. **数据集身份与多种文件格式**：以内部 XLSX 内容的 `workbook_sha256` 加清洗/转换版本创建稳定的有效快照身份，`submitted_file_sha256` 记录实际上传容器。官方 ZIP 与其内部原 XLSX 内容相同只能导入一次。对外 `data_hash` 指向本次实际有效的 workbook/snapshot 内容哈希，报告中不要将 ZIP 的哈希伪装成工作表哈希。`raw_sha256` 字段在实现中需明确其含义，更新 OpenAPI/数据字典，不允许同时被解释为 ZIP 与 XLSX。
2. **导入状态与崩溃**：`IMPORTING` 的数据不可对外显示为完成快照；只有逐行完成、校验分类计数并提交成功，才标 `READY`。失败要保存 ImportBatch 错误，恢复要么清理不完整批次重新导入，要么在真实断点/行唯一键下安全续跑，不能暴露部分金额为完整结果。避免将 54 万行同步塞进单个 HTTP 请求循环并使浏览器无限等待。首版可采用一个本地受控后台执行器并轮询状态，不要求 Celery。
3. **精确价格与原值**：当前 UCI 已审核版本按 0.001 GBP 网格规范化，存整数千分英镑；如果 openpyxl/pandas 返回浮点，不能声称它就是 OOXML 原始数字字符串。要明确区分原始单元格文本/OOXML 表示、解析后的 Decimal 和规范化结果；超阈值必须报错/标无效，不能静默精度损失。显示金额应先在服务端用 Decimal 计算并返回明确的两位小数字符串，避免 JS Number 影响核对。
4. **行分类与取消条件**：C/c 发票且数量为正或零应归 `EXCLUDED_OTHER`；其余分类和金额见 `13_ECOMMERCE_BUILD_CONTRACT.md`，`INVALID` 行要保留可追溯来源与原因。原始“疑似重复”只做质量提示，绝不能等同于重复文件导入。
5. **空结果与无数据**：数据快照/月份完全不在覆盖范围，返回 `NO_DATA`；处于覆盖区间内但符合过滤条件的行数为0时，要区分“合法的零结果”和“数据不存在”。2011-12是 `PARTIAL_PERIOD`，不能用零收入代替覆盖提示。接口的错误码与HTTP状态在 OpenAPI 中规范化并测试。
6. **单一接口基址**：外部业务API统一 `/api/v1`，健康 `/healthz`；不要给 `POST /runs` 再建另一套公开接口。五个视图可合并路由，**不合并或删除功能**。对未来仍未开发的 API 返回明确的能力不可用，不用 200 + 假数据。
7. **报告与证据**：最终金额、涨跌幅和排名由服务端从存储的 `tool_call_id` / `field_path` / 版本与过滤器得到；报告引用必须能追溯到真实结果。模型可以写解释，但未经依据的因果陈述不能标为确定事实；功能验收包含一次精确数字错误被拒绝的负例。
8. **运行恢复**：LangGraph使用与锁定版本兼容的 `langgraph-checkpoint-sqlite`；检查真实 `thread_id`、checkpoint生命周期以及反复恢复的副作用。需要时按[官方checkpoint SQLite包](https://github.com/langchain-ai/langgraph/blob/main/libs/checkpoint-sqlite/README.md)的当前安全建议设置安全的 checkpoint 反序列化限制（例如所锁定版本支持的 `LANGGRAPH_STRICT_MSGPACK=true` 或允许模块白名单）；不能无条件加载不可信检查点。`WAITING_INPUT` 必须能跨重启恢复并防止双份报告；`GET`历史必须纯读取。
9. **模型阶段门槛**：没有授权的模型额度就先完成 provider adapter、fake-provider 工程测试与工具和页面。正式真实模型调用只在明确有授权的正数总预算、独立任务上限、可解析实际 provider/ID 后进行；未知 token 和供应商计费不能写0，也不得创建自带自动充值的流程。
10. **当前交付阶段**：D0—D9 是功能开发和系统测试；论文正文及正式批量 B0/B1/B2 对照保持延期。保留开发 trace/测试，但不生成学术试验结果。
